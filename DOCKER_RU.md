# Docker: что это и как он используется в Tabi

Docker — инструмент для запуска приложений в контейнерах. Контейнер — отдельное окружение для процесса: внутри есть нужные файлы и зависимости. Это не база данных и не хостинг.

В нашем проекте два контейнера:

```text
Браузер → localhost:5173 → app: Node.js + Express + собранный React
                                     ↓
                             db: PostgreSQL
                                     ↓
                         volume: сохранённые поездки
```

**Image (образ)** — шаблон с программой и её окружением. **Container (контейнер)** — запущенный экземпляр образа. **Volume (том)** — постоянное хранилище вне файловой системы контейнера. **Docker Compose** читает `compose.yaml` и управляет несколькими сервисами вместе.

`Dockerfile` описывает сборку нашего приложения: установить зависимости, проверить TypeScript, собрать React, запустить сервер. Для PostgreSQL используем готовый официальный образ. Compose ждёт готовности базы, затем запускает приложение.

## Запустить

Открой Docker Desktop и дождись запуска engine. В терминале:

```sh
cd "/Users/rohen/Intern project"
docker compose up -d --build --wait
```

При первой установке на другом компьютере сначала скопируй `.env.example` в `.env` и задай свой локальный пароль. На этом компьютере файл уже подготовлен. Не перезаписывай существующий `.env` без необходимости.

Открывай http://127.0.0.1:5173. `-d` запускает контейнеры в фоне, `--build` пересобирает приложение после изменения кода, `--wait` ждёт готовности сервисов.

Если терминал пишет `command not found: docker`, на этом Mac можно использовать полный путь `~/.docker/bin/docker` вместо `docker`.

## Остановить и запустить снова

```sh
docker compose stop
docker compose start
```

При обычной остановке база сохраняется. Команда `docker compose down` убирает контейнеры и сеть, но сохраняет именованный том. **Не добавляй `-v`, если хочешь сохранить поездки:** этот флаг удаляет том с базой.

## Посмотреть состояние и логи

```sh
docker compose ps
docker compose logs --tail=50 app
docker compose logs --tail=50 db
```

## Посмотреть настоящую базу

```sh
docker compose exec db psql -U tabi -d tabi
```

В SQL-консоли:

```sql
SELECT id, data->>'name' AS trip_name, created_at FROM trips;
```

Выход: `\q`. Таблица `trips` содержит ID, JSONB-снимок поездки и время создания. Она создаётся сервером при запуске. Случайный пароль хранится в локальном `.env`, который исключён из Git и Docker-образа.

Внутри Docker приложение обращается к базе как `db:5432`: `db` — имя сервиса. С твоего Mac подключение идёт на `127.0.0.1:5433`. Это разные адреса одной базы для разных сетевых окружений.

## Docker и разработка

После изменения исходников при запуске в Docker нужен `docker compose up -d --build --wait`. Для быстрой разработки удобнее `npm run dev`: изменения интерфейса видны сразу. По умолчанию этот режим использует SQLite; PostgreSQL включается через `DATABASE_URL`.

Не запускай две копии приложения на одном порту. Если нужен режим npm на 5173, сначала выполни `docker compose stop app`. SQLite-файл и PostgreSQL-том — разные базы; старые SQLite-поездки не переносятся автоматически.

## А деплой?

Образ можно запустить на другом сервере, но локальный Docker не делает сайт публичным. Для деплоя понадобятся хостинг, домен/HTTPS, секреты, резервное копирование и решение о доступе к сохранённым поездкам. Сейчас API намеренно принимает только локальные имена хоста и не имеет пользовательской авторизации.

Официальные материалы: [Docker Compose](https://docs.docker.com/compose/) и [контейнер PostgreSQL с постоянным хранилищем](https://docs.docker.com/guides/postgresql/immediate-setup-and-data-persistence/).
